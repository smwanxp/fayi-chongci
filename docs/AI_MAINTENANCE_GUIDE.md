# 法忆冲刺：AI 与开发者维护指南

本文面向接手项目的 AI 或开发者。开源仓库不包含正式题库、用户数据和任何线上应用凭据。

## 1. 项目边界

- 前端：`client/src`
- 后端：`server`
- 前后端共享类型：`shared`
- 单元测试：`test/unit`
- 示例内容：`client/src/lib/seed.ts`、`client/src/lib/daily-questions/index.ts`
- 使用说明：`docs/USER_GUIDE.md`

题库内容与程序代码必须分开管理。不得把商业教辅、真实用户备份、生产数据库导出、密码、令牌、Cookie、应用密钥或线上存储标识提交到公开仓库。

## 2. 架构概要

前端采用 React、TypeScript、Vite 和 IndexedDB。学习操作先落到本机数据仓库，再由同步层上传。后端采用 NestJS，负责当前用户的数据读写、管理员内容同步和权限校验。

关键模块：

- `client/src/lib/repository.ts`：本地数据仓库与同步调度。
- `client/src/lib/scheduler.ts`：固定曲线、自适应间隔和考试日期封顶。
- `client/src/lib/cloud-payload.ts`：公共内容、用户内容和个人学习状态的云端封装。
- `client/src/components/fayi/PracticeModes.tsx`：速记、带背和考试式练习。
- `client/src/components/fayi/Notebook.tsx`：独立复习笔记体系。
- `server/modules/study-data`：当前用户云端数据。
- `server/modules/admin`：管理员用户、备注和内容同步。
- `shared/api.interface.ts`：前后端协议，修改时必须同时检查两端。

## 3. 数据原则

1. `Subject / Chapter / Card / Relation / DailyQuestion` 是可共享学习内容。
2. 掌握度、复习日志、错题、笔记、设置和进行中的试卷属于个人数据。
3. 管理员同步内容时不得覆盖学生个人数据。
4. 公共内容可放在文件存储；数据库只保存内容差异和文件指针。
5. 个人学习状态应使用每用户独立文件，避免每次答题重写大型数据库 JSON。
6. 导入失败只能产生草稿或错误记录，不能污染正式题库。

## 4. 添加自己的内容

开源版只提供虚构示例。维护者可以：

- 通过管理员页面逐条添加卡片或每日一题；
- 使用资料导入功能生成草稿并人工确认；
- 在私有分支替换 `seed.ts` 和 `daily-questions/index.ts`；
- 使用 `scripts/export-storage-content.ts` 生成公共内容文件。

内容必须拥有合法使用和传播权限。私有题库文件建议放在独立私有仓库，或通过部署时的文件存储注入，不要合并回公开分支。

## 5. 环境配置

复制 `.env.example`，仅在本地或部署平台填写真实值。所有 `.env*` 文件默认被忽略，只有 `.env.example` 可以提交。

飞书部署需要在自己的应用中创建数据库、角色和文件存储桶。不要复用他人的任何 ID。公共文件存储的非敏感标识统一放在 `client/src/lib/deployment-config.ts`；密码、令牌和应用密钥仍只能放在本地环境变量或部署平台的密钥设置中。

## 6. 修改流程

1. 先查看 `git status`，不要覆盖无关改动。
2. 阅读受影响模块及其类型定义。
3. 实施最小范围修改。
4. 增加或更新单元测试。
5. 依次运行类型检查、测试、代码检查和生产构建。
6. 使用测试账号做登录、学习、刷新和恢复数据的冒烟测试。
7. 数据结构变化必须验证旧数据升级，不得要求用户无条件清库。

标准检查：

```bash
npm run type:check
npm test -- --runInBand
npm run eslint
npm run build:prod
```

## 7. 权限与安全

- 不开放匿名注册；账号和角色由部署者管理。
- 服务端必须以可信身份确定当前用户，不能接受客户端任意指定用户 ID。
- 管理员接口必须同时校验登录状态和管理员角色。
- 不在日志中输出请求正文、密码、令牌或完整学习备份。
- 删除数据前必须明确范围，并优先提供备份或可恢复机制。
- 公共仓库提交前运行密钥扫描，并检查整个暂存区。

## 8. 发布前检查

- 类型检查、测试和生产构建全部通过。
- 新旧账号均能打开应用。
- 学习进度刷新后仍存在。
- 管理员同步不覆盖学生个人状态。
- 文件存储失败时给出明确错误，不静默清空数据。
- 数据库写入量没有因高频答题而持续放大。
- Git 中没有环境文件、应用元数据、用户数据或正式题库。

## 9. 禁止事项

- 不提交真实 `.env`、线上应用元数据或数据库导出。
- 不把正式题库重新加入公开仓库。
- 不伪造法律结论、题目答案或来源。
- 不绕过测试直接发布。
- 不将一个用户的笔记、错题或进度同步给其他用户。
- 不用破坏性 Git 或数据库命令解决普通迁移问题。
